一、项目目标

这是一个超市场景的机械臂视觉抓取系统：

RealSense 腕部相机采集 RGB-D -> Qwen2.5-VL 识别目标并输出 bbox -> ROS2 抓取节点保存当前 RGB-D 帧 -> realsense_click_grasp.py 使用 GraspNet 生成抓取姿态 -> 转换到 RealMan 基座坐标 -> CuRobo 做 IK/轨迹检查 -> 发布 ROS2 PoseStamped -> RealMan/CuRobo 执行或 PLAN_ONLY。

目前主要使用右臂，也保留左臂配置。左臂和右臂必须使用各自的相机、机器人 IP、标定矩阵和基座坐标转换，不能把两个基座当成同一个坐标系。

四、坐标系约定

GraspNet 输出的是虚拟夹爪坐标系中的姿态，RealSense optical frame 轴为：
   +X 向右，+Y 向下，+Z 向前。

基本变换：
   T_base_grasp = T_base_flange * T_flange_camera * T_camera_grasp

位置：
   p_base_grasp = p_base_flange + R_base_flange * (
       p_flange_camera + R_flange_camera * p_camera_grasp
   )

旋转：
   R_base_grasp = R_base_flange * R_flange_camera * R_camera_grasp

T_grasp_model_tcp 用于把 GraspNet 虚拟夹爪坐标转换到实际 TCP/工具坐标。必须确认矩阵方向，不能凭感觉新增旋转矩阵。

右臂和左臂的 RealMan 基座不是同一个坐标系。当前左臂还涉及 RealMan base 到 CuRobo driver_base 的轴变换：
   p_curobo = [-z_realman, y_realman, x_realman]
具体旋转也应在代码和 Open3D 轴显示中核对。

五、approach 和姿态逻辑

当前设计目标是：先用视觉/GraspNet选位置，再按 align-base-z 对齐 TCP +Z，最后依据 approach 构造虚拟夹爪 +X 的方向，不再依赖原始 GraspNet approach 方向。

当 --align-base-z y 时，TCP/虚拟夹爪 +Z 与参考基座方向平行；由 --base-z-direction positive/negative 决定同向或反向。

用户给出的最终方向约定：

左臂：
   approach=left  -> 虚拟夹爪 +X 指向左基座 -Z
   approach=right -> 虚拟夹爪 +X 指向左基座 +Z
   approach=front -> 虚拟夹爪 +X 指向左基座 -Y

右臂：
   approach=left  -> 虚拟夹爪 +X 指向右基座 +X
   approach=right -> 虚拟夹爪 +X 指向右基座 -X
   approach=front -> 虚拟夹爪 +X 指向右基座 -Y

虚拟夹爪开口/接近方向当前按 +X 处理。+Y 是夹爪闭合方向，+Z 是工具轴方向。实际安装后，必须用实物 TCP 轴定义验证。

--angle 的设计是：在 approach 和 base-Z 对齐完成后，绕圆柱轴/对齐轴旋转虚拟夹爪方向。它不是平移参数。

--cylinder-axis-centering y 的含义：让虚拟夹爪 +X 朝向圆柱轴线，通常会重新调整姿态，不能把它理解成单纯移动夹爪 XYZ。当前默认应保持打开，除非需要诊断。

虚拟圆柱相关参数：
   --cylinder-diameter-scale：物体估计直径的缩放比例。
   --cylinder-height-scale：圆柱轴向高度缩放。
   --cylinder-forward-offset：圆柱向相机方向的偏移。
   --cylinder-front-fraction：只保留相机前方的圆柱周向比例。
   --cylinder-surface：限制姿态位于 front/left/right/any 表面区域。
   --cylinder-surface-angle：表面角度容差。
   --cylinder-grasp-height-fraction：沿物体高度抓取的位置，当前常见默认约 0.58，表示中间偏上。

八、抓取服务正确顺序

1. 先启动 RealMan 驱动。
2. 启动 RealSense ROS 相机，并确认彩色、深度、camera_info 话题存在。
3. 启动 Qwen 节点。
4. 启动 grasp.launch.py 或 UI 后端。
5. 给 Qwen 发送目标关键词，等待 /qwen_vl/right/result 出现 accepted 结果。
6. 结果必须在 detection_timeout_s 有效期内。
7. 调用抓取服务：

source /opt/ros/humble/setup.bash
source /home/lh/robot/install/setup.bash
export AMENT_PREFIX_PATH=/home/lh/robot/install/qwen2_5_vl_ros2:/home/lh/robot/install/supermarket_grasp_ros2:${AMENT_PREFIX_PATH}
ros2 service call /right/grasp/trigger std_srvs/srv/Trigger '{}'

如果返回：
   No accepted Qwen result received
说明没有先发送关键词/没有 accepted 结果。

如果返回：
   ROS frame or YOLO detection is stale; ages ... detection=...
说明 Qwen 检测已经过期。重新发送关键词，或者提高 grasp.launch.py 的 detection_timeout_s。

   - 单独运行通常采集的是新的 RealSense 帧。
   - 单独运行通常使用手动四点区域，不是 Qwen bbox。
   - ROS UI 使用保存的 frame_bundle 和自动 bbox。
   - make_selected_cloud 使用随机点采样，重复运行本身也可能得到不同候选数。
   - ROS 相机和独立 Python 的帧率/深度状态也可能不同。

因此两次运行不是同一输入，不能只比较命令行参数。

十、当前失败的诊断命令

在 grasp 节点运行时临时设置：

source /opt/ros/humble/setup.bash
source /home/lh/robot/install/setup.bash
export AMENT_PREFIX_PATH=/home/lh/robot/install/qwen2_5_vl_ros2:/home/lh/robot/install/supermarket_grasp_ros2:${AMENT_PREFIX_PATH}
ros2 param set /supermarket_grasp extra_args \
'--open y --align-base-z y --select-best 3 --angle 0 --approach any --collision-thresh -1'

然后重新调用：

ros2 service call /right/grasp/trigger std_srvs/srv/Trigger '{}'

解释：
   --collision-thresh -1 只用于诊断，临时跳过 GraspNet 碰撞过滤。
   如果候选从 0 变为大于 0，说明碰撞阈值/点云碰撞过滤太严格。
   如果仍为 0，说明问题在 ROS 帧、bbox、深度掩码、虚拟圆柱或 GraspNet 本身。

再诊断虚拟圆柱：

ros2 param set /supermarket_grasp extra_args \
'--open n --align-base-z n --select-best 3 --angle 0 --approach any --collision-thresh -1'
ros2 service call /right/grasp/trigger std_srvs/srv/Trigger '{}'

如果 --open n 能生成姿态而 --open y 不能，问题就在虚拟圆柱点云参数，例如直径太小、深度估计错误、圆柱高度/前向偏移不合适。

十一、不要混淆的事项

1. --top-k 只限制最终保留的候选数量，不能让 0 个候选变成非 0。
2. --select-best 只从已有候选中选择，不能生成候选。
3. --approach any 只放宽方向筛选；如果 GraspNet 初始候选就是 0，它没有作用。
4. CuRobo 只在最终姿态候选存在后检查 IK/轨迹；当前最新失败不是 CuRobo 拒绝。
5. detection_timeout_s 只控制 Qwen 结果是否过期，不会提高 GraspNet 成功率。
6. target_label 为空字符串在 ros2 launch 命令行中容易造成 malformed launch argument。
7. RealSense 的 “Depth stream start failure” 或 “Right MIPI error” 是相机/USB/设备占用问题，需要先解决。

十二、建议的后续开发

优先级 1：给 grasp_node 增加 debug_keep_frame 参数，失败时保留 frame_bundle、bbox、mask 和虚拟圆柱点云，便于完全复现。

优先级 2：增加确定性调试选项，例如 --seed，避免 make_selected_cloud 和虚拟圆柱随机采样导致同一帧结果不一致。

优先级 3：把 bbox mask 可视化保存为 PNG，并输出有效深度占比、深度中位数、点云 XYZ 范围。

优先级 4：在 UI 中将“Qwen 检测框”和“实际 GraspNet 使用的深度掩码”同时显示，避免框很大或包含背景时误判。

优先级 5：若 --collision-thresh -1 能恢复候选，再重新调 collision_thresh、voxel_size 和物体 ROI，不要直接关闭碰撞过滤用于真实抓取。
