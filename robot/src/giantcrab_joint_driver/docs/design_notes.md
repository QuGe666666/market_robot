
# 运行原理补充说明

## A. 为什么这版包故意不做复杂框架

你的现场已经证明：

- 简单直接的 `OpenDevice -> SetBaud -> InitCAN -> StartCAN -> SDO`
- 比复杂的“多后端 + 看门狗 + 额外状态机”更容易先稳定跑起来

所以这版包的目标是：
**先把最核心的关节控制服务做成一个干净、可维护、能长期改的 ROS2 包。**

## B. 为什么不调用 ZCAN_SetResistanceEnable

因为你前面真实测试已经出现过：
- `ZCAN_OpenDevice` 后正常
- 一进 `ZCAN_SetResistanceEnable` 就 `exit code -11`

所以这版明确跳过这一步，把终端电阻控制交回物理接线。

## C. 为什么只做软件限位

当前你掌握的协议资料足够支持：
- 位置读写
- 状态读写
- 清故障
- 设零位

但“硬件限位对象字典”没有完全确认。  
因此本包先做软件限位，避免误写未知对象导致行为不可控。

## D. 这版和你那份旧可用程序的关系

这版不是推翻旧程序，而是：
- 保留它“简单直接、少步骤、已验证”的底层思路
- 修掉旧程序里几个明显的坑：
  - 清故障对象写错
  - 负数位置没有按 32 位补码正确编码
  - 没有校验 SDO 响应是不是当前请求
  - 读位置时只拿了 16 位
  - 多线程共享发送/接收通道时无锁
