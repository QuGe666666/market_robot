# 双臂超市抓取主程序部署说明

> 适用目录：`/home/lh/robot`  
> 适用系统：Ubuntu 22.04、ROS 2 Humble、aarch64/Jetson AGX Orin 64GB  
> 文档依据：当前工作区源码与 Launch 参数，更新日期：2026-09-14

## 1. 文档目的

本文说明双臂超市抓取比赛主程序的部署、配置、启动、验证、停机和常见故障处理方法。

当前正式主入口是：

```bash
ros2 launch supermarket_pick_sequence competition_system.launch.py
```

根目录的 `start_supermarket_ui_clean.sh` **只启动 Qt 界面**，不会启动比赛 FSM、相机、机械臂、底盘和算法节点，因此不能作为完整系统的一键启动入口。

## 2. 当前功能范围

主程序由 Qt 比赛控制台、Competition FSM、底盘、升降机构、双 RM65 机械臂、双 OmniPicker 夹爪、双腕 RealSense、YOLO、Qwen2.5-VL、GraspNet 和 CuRobo 组成。

主要功能如下：

- 在 Qt 界面选择 1 个箱型和 4 个商品，发送任务并控制开始、暂停、继续、停止和复位。
- 校验 4 种箱体和 16 种商品的任务配置。
- 根据箱体或商品配置自动选择导航点、工作臂、升降高度、YOLO 标签、Qwen 提示词和抓取角度。
- 商品识别优先使用 YOLO，失败后使用 Qwen2.5-VL 兜底。
- 使用 RGB-D 数据和 GraspNet 生成抓取候选。
- 使用 CuRobo 完成 IK、碰撞和轨迹检查，并支持 `current -> pregrasp -> grasp` 分阶段规划。
- 箱体采用双臂同步抓取，商品根据配置使用左臂或右臂抓取。
- 使用真实导航、升降、关节、夹爪位置和算法结果反馈推进状态机，不用固定延时假定动作成功。
- 停止或错误时取消导航，停止底盘、升降和机械臂，并保持夹爪状态；系统不会在异常时自动打开夹爪。

当前比赛流程为：

```text
系统初始化与硬件门禁
  -> 接收并校验任务
  -> 到 B/C 点抓取空箱
  -> 底盘后退 0.50 m、旋转 180 度
  -> 到 J 点放置空箱
  -> 依次或按双臂批次抓取 4 个商品
  -> 每批商品送到 J 点并放入箱中
  -> 在 J 点双臂抓取满载箱
  -> 运送到 A 点并放下
  -> 比赛完成
```

说明：部分旧文档仍记录放置区 `G` 和后退 `0.40 m`。当前程序以 `competition_fsm/state_machine.py` 与 `config/fsm.yaml` 为准，实际使用 `J` 和 `0.50 m`。

## 3. 软件结构

| 模块 | ROS 2 包 | 作用 |
|---|---|---|
| 总控 | `supermarket_pick_sequence` | 比赛 FSM、任务配置、硬件协调、总 Launch |
| 操作界面 | `supermarket_grasp_ui` | Qt 比赛控制台、任务输入、状态和相机显示 |
| 快速检测 | `yolov8_ros2` | 左右相机 YOLO 检测 |
| 语义兜底 | `qwen2_5_vl_ros2` | Qwen2.5-VL 目标定位、深度与坐标校验 |
| 抓取生成 | `supermarket_grasp_ros2` | 同步 RGB-D、调用 GraspNet、发布候选姿态 |
| 规划执行 | `curobo_realman_test` | 双 RM65 驱动、腕部 TF、CuRobo 规划与执行 |
| 夹爪 | `omnipicker_gripper` | 经机械臂末端 RS485 控制双 OmniPicker |
| 底盘适配 | `chassis_ros`、`lh_chassis_bridge` | Woosh Agent 兼容、导航 Action、里程计和停止服务 |
| 相机 | `realsense2_camera` | 左右腕 RGB-D 图像和内参 |
| 机械臂驱动 | `rm_driver` | RM65 状态反馈和运动控制 |

Qt 只向 FSM 发布任务和控制命令，不直接操作硬件。所有动作都由 FSM 统一调度。

## 4. 部署前提与限制

### 4.1 推荐硬件环境

- Jetson AGX Orin 64GB。
- Ubuntu 22.04 aarch64。
- ROS 2 Humble Desktop。
- 可用的 NVIDIA JetPack/CUDA 环境；现有 Qwen 文档对应 CUDA 12.6、PyTorch 2.5 CUDA。
- 至少 40 GB 可用磁盘空间。当前 Qwen 模型目录约 23 GB，Grounded-SAM2 模型约 1.6 GB，另需预留构建、日志和运行空间。
- 本地图形桌面或正确配置的 X11 转发环境，用于显示 PyQt5 控制台。

### 4.2 新机器复现限制

当前工程是现场工作区，不是完全自包含的安装包。以下内容依赖现有机器环境：

- `/home/lh/miniconda3/envs/robot`：ROS Python/TF 辅助节点使用。
- `/home/lh/miniconda3/envs/grasp`：GraspNet 脚本使用。
- `/home/lh/robot_env/lerobot-realman-orin`：CuRobo 容器项目。
- `/home/lh/CW/yolo/best.pt`：总 Launch 当前实际引用的 YOLO 权重。
- Woosh 厂商 deb、RealMan 驱动及其本地库。
- GraspNet/CuRobo 依赖、模型和本机 CUDA 适配包。

仓库当前没有完整的 Conda `environment.yml`、Python 锁文件或完整容器镜像导出。因此：

- **同机重部署**：可以按本文直接编译和启动。
- **迁移到新机**：建议整体迁移两个 Conda 环境和 CuRobo 容器工程，或先补齐依赖锁文件后再部署。
- 只执行 `rosdep install` 不能自动复现 GraspNet、CuRobo、Jetson PyTorch 和厂商 SDK。

```bash

sudo apt install -y \
  ros-humble-desktop \
  python3-colcon-common-extensions \
  python3-rosdep \
  python3-opencv \
  python3-pyqt5 \
  python3-pyqt5.qtsvg \
  python3-vtk9 \
  ros-humble-cv-bridge \
  ros-humble-diagnostic-updater \
  ros-humble-control-msgs
```

安装可由 rosdep 解析的依赖：

```bash

```

如果厂商自定义包无法由 rosdep 解析，应先安装 `src/debs` 中与当前 aarch64/Ubuntu 版本匹配的 Woosh deb，并按 `src/ros2_rm_robot-humble/rm_driver/lib/lib_install.sh` 安装 RealMan 库。不要在不确认架构和版本时强行安装 deb。

## 7. 编译工作区

ROS 2 包使用系统 Python 3.10 编译，不要在 Conda 激活状态下执行 colcon：

```bash

unset PYTHONPATH
unset AMENT_PREFIX_PATH
unset COLCON_PREFIX_PATH
unset PYTHON_EXECUTABLE
unset Python3_EXECUTABLE

source /opt/ros/humble/setup.bash
cd /home/lh/robot
/usr/bin/python3 -m colcon build \
  --packages-up-to supermarket_pick_sequence supermarket_grasp_ui \
  --symlink-install
```

如果这是包含全部厂商源码的新工作区，且依赖已经完整安装，也可以执行：

```bash
cd /home/lh/robot
source /opt/ros/humble/setup.bash
/usr/bin/python3 -m colcon build --symlink-install
```

编译后加载环境并检查关键包：

```bash
source /opt/ros/humble/setup.bash

for pkg in \
  supermarket_pick_sequence supermarket_grasp_ui yolov8_ros2 \
  qwen2_5_vl_ros2 supermarket_grasp_ros2 curobo_realman_test \

  ros2 pkg prefix "$pkg" || exit 1

```

以后每个新终端至少执行：

```bash

```

所有终端和容器必须使用相同的 `ROS_DOMAIN_ID`。当前机器环境使用 `42`，建议每个运行终端都显式设置：

## 9. 分级启动与验证

必须按以下顺序从无硬件模式逐级验证。不要第一次部署就直接启用真机运动。

### 9.1 一级：完整 mock 联调

此模式不连接真实硬件，也不加载算法模型，用于验证 Qt、任务通信和完整 FSM：

```bash
cd /home/lh/robot
source /opt/ros/humble/setup.bash
source /home/lh/robot/install/setup.bash
ros2 launch supermarket_pick_sequence competition_system.launch.py mock:=true
```

在界面中选择箱型和 4 个商品，点击“发送并开始”。预期状态自动推进到 `COMPETITION_FINISHED`。

没有桌面显示时可使用：

```bash
ros2 launch supermarket_pick_sequence competition_system.launch.py \
  mock:=true qt_platform:=offscreen
```

### 9.2 二级：算法加载、硬件关闭

此模式加载 Qwen、YOLO、GraspNet 和 CuRobo，但不启动底盘、相机、机械臂和夹爪驱动：

```bash
ros2 launch supermarket_pick_sequence competition_system.launch.py \
  mock:=false \
  mock_hardware:=true \
  run_algorithm_nodes:=true \
  execute:=false \
  require_chassis_odom:=false \
  qt_platform:=offscreen
```

预期结果：各算法成功加载；由于 `execute:=false`，从 Qt 点击开始会被真实执行安全锁拒绝。这是正确行为。该模式只验证进程、模型和 ROS 接口，不验证动作。

### 9.3 三级：真实设备连接检查，不开始任务

以下命令会连接真实设备并启动全部组件，但没有真实执行令牌，FSM 不允许开始运动：

```bash
ros2 launch supermarket_pick_sequence competition_system.launch.py \
  mock:=false \
  execute:=false \
  right_gripper_id:=<现场确认的ID>
```

启动后不要点击开始。按第 10 节检查全部节点、话题、服务和反馈。此模式仍可能初始化夹爪工具电源、建立机械臂和底盘连接，因此必须保证现场急停可用、机械臂周围无人且工作区无障碍物。

### 9.4 四级：真机执行

只有完成现场验收清单后才运行：

```bash
cd /home/lh/robot
source /opt/ros/humble/setup.bash
source /home/lh/robot/install/setup.bash

ros2 launch supermarket_pick_sequence competition_system.launch.py \
  mock:=false \
  execute:=true \
  execution_token:=I_UNDERSTAND_REAL_ROBOT_MOTION \
  right_gripper_id:=<现场确认的ID>
```

如果现场参数不同，可以显式覆盖：

```bash
ros2 launch supermarket_pick_sequence competition_system.launch.py \
  mock:=false execute:=true \
  execution_token:=I_UNDERSTAND_REAL_ROBOT_MOTION \
  chassis_host:=169.254.128.2 chassis_port:=5410 \
  left_arm_ip:=169.254.128.18 right_arm_ip:=169.254.128.19 \
  robot_host_ip:=169.254.128.100 \
  left_udp_port:=8089 right_udp_port:=8090 \
  left_gripper_id:=2 right_gripper_id:=<现场确认的ID>
```

`execute:=true` 和正确的 `execution_token` 必须同时存在。缺少任一项，FSM 会拒绝开始真实任务。

## 11. 操作流程

1. 确认急停、限位、机械臂初始姿态、底盘地图和现场净空。
2. 启动总 Launch，等待 Qwen、GraspNet 和 CuRobo 完成模型加载与预热。
3. 观察 Qt 健康状态和 `/competition/status`，确认初始化门禁全部就绪。
4. 在 Qt 选择正确箱型和 4 个商品，检查自动映射出的机械臂、货架点和高度。
5. 发送任务，再点击开始。
6. 运行中重点观察导航目标、升降实际高度、活动机械臂、检测后端、抓取候选、CuRobo 状态和夹爪反馈。
7. 临时中止使用“暂停”；暂停会触发硬件安全停止。确认现场状态后才能继续。
8. 异常时使用“停止”或物理急停。软件停止保持夹爪，不会自动释放已经抓取的物体。
9. 排除故障后使用“复位”，重新检查门禁并重新下发任务。

## 12. 安全要求

- 第一次真机部署必须先低速、单动作、空载验证，再运行完整比赛流程。
- 操作人员必须能随时触及物理急停，机器人工作区内不得站人。
- 启动前确认左右臂没有重复驱动连接。
- 底盘运动前机械臂必须处于安全收回位；升降运动前机械臂不得伸展到碰撞区域。
- 双臂箱体抓取必须等待左右规划和执行 barrier，不能手动绕过单侧失败。
- 不得通过伪造 `ACTION_COMPLETE`、关节反馈、到达帧或夹爪成功消息驱动真机 FSM。
- `holding_status_code` 当前为 `-1`，表示未启用固件夹持状态码判定。正式验收时应确认寄存器 21 的现场含义，否则系统只能依据服务成功和位置有效性判断。
- 当前 NVBlox 默认关闭，系统没有使用在线三维体素地图作为动态障碍保护。现场必须依靠静态规划边界、净空和人工监护。

## 13. 正常停机

1. 在 Qt 点击“停止”，等待状态进入 `SAFE_STOP`。
2. 确认底盘、升降和双臂已经停止。
3. 如果夹爪仍夹持物体，在人工确认安全后单独释放，不能假定停止命令会自动打开夹爪。
4. 回到启动终端按 `Ctrl+C`，等待所有子进程退出。
5. 检查是否残留主程序进程：

```bash
pgrep -af 'competition_system|competition_fsm|supermarket_grasp|qwen2_5_vl|yolov8|curobo|rm_driver|omnipicker|realsense'
```

只在确认是本系统残留进程后再终止，避免影响同机其他 ROS 任务。

## 14. 常见故障

### 14.1 Qt 无法打开

检查：

```bash
echo "$DISPLAY"
echo "$XAUTHORITY"
```

本机 X11 通常使用 `qt_platform:=xcb`。远程无界面验证使用 `qt_platform:=offscreen`。不要在 offscreen 模式下期待看到窗口。

### 14.2 FSM 停在 `INIT_BARRIER`

读取完整状态：

```bash
ros2 topic echo /competition/status
```

逐项检查底盘里程计、左右关节、升降、夹爪位置有效性、两路相机、YOLO、Qwen、GraspNet、CuRobo 和 TF。没有真实反馈时停在门禁是正常安全行为。

仅诊断时可以传 `require_chassis_odom:=false`，但正式运行不得用它掩盖底盘里程计故障，因为后退距离仍依赖 odom。

### 14.3 话题存在但没有数据

```bash
ros2 topic info /chassis/odom --verbose
ros2 topic hz /chassis/odom
ros2 daemon stop
ros2 daemon start
```

确认所有进程的 `ROS_DOMAIN_ID` 一致，并检查 QoS、网卡、容器网络和 Publisher/Subscriber 数量。只看到话题名称不代表数据链路正常。

### 14.4 RealSense 启动失败

- 确认两台设备均被 `rs-enumerate-devices -s` 识别。
- 检查序列号是否传反、USB 带宽和供电是否充足。
- 检查是否已经有另一个 RealSense 节点占用设备。
- 检查彩色、深度、对齐深度和 CameraInfo 四类话题是否实际发布。

### 14.5 Qwen 加载失败或 CUDA 内存不足

- 检查模型目录完整性和 PyTorch CUDA 可用性。
- 停止 Grounded-SAM2 等不属于当前总 Launch 的常驻 GPU 进程。
- 使用 `tegrastats` 检查内存和 GPU 占用。
- 不要同时启动第二个 Qwen 节点；当前双臂模式在一个节点内只加载一次 7B 模型。

### 14.6 YOLO 找不到权重

确认 `/home/lh/CW/yolo/best.pt` 存在。总 Launch 当前没有使用包内 `best.pt`。迁移目录后应修改 Launch 参数源并重新编译。

### 14.7 CuRobo 没有状态发布或启动即退出

```bash
ros2 topic info /left/curobo/status --verbose
ros2 topic info /right/curobo/status --verbose
docker ps
```

检查 `/home/lh/robot_env/lerobot-realman-orin`、容器镜像、CUDA 映射、`run_curobo_node` 和单实例锁。CuRobo 进程退出会触发总 Launch 关闭，这是设计行为。

### 14.8 夹爪服务存在但不动作

- 确认左右机械臂 IP 可达、末端工具电压为 24 V、RS485 为 115200 8N1。
- 确认 Modbus 端口为 `1`，左右从站 ID 与现场一致且互不相同。
- 查看 `position_valid` 和 `status`，不要只依据服务返回判断。
- 总 Launch 当前右夹爪默认 ID 为 `1`，与夹爪包文档的 `3` 不一致，必须现场确认。

### 14.9 修改源码或配置后行为未变化

重新构建并 source：

```bash
cd /home/lh/robot
source /opt/ros/humble/setup.bash
/usr/bin/python3 -m colcon build \
  --packages-up-to supermarket_pick_sequence supermarket_grasp_ui \
  --symlink-install
source /home/lh/robot/install/setup.bash
```

用 `ros2 pkg prefix <包名>` 确认加载的是 `/home/lh/robot/install`，避免误用旧工作区。
